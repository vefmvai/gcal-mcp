# gcal-mcp

MCP-сервер к Google Календарю: посмотреть события, найти нужное по названию,
увидеть свободные окна, создать и перенести встречу.

Сервер маленький и делает одно дело. Его может звать любой агент — это
инструмент к Календарю, а не часть какого-то конкретного помощника.

## Что умеет

| Кнопка | Что делает |
|---|---|
| `list_calendars` | Все доступные календари и их id |
| `list_events` | События за период: сегодня, завтра, неделя или свой отрезок |
| `find_events` | Найти событие по словам в названии, когда id неизвестен |
| `free_slots` | Свободные окна — что **не** занято, сразу по нескольким календарям |
| `create_event` | Создать событие |
| `update_event` | Перенести или изменить |
| `delete_event` | Удалить |

Точный список всегда можно напечатать командой — он берётся из кода,
а не из этой таблицы:

```bash
gcal-mcp-tools
```

Про `free_slots` стоит сказать отдельно: обычный список событий отвечает
на вопрос «что занято», а планировать день приходится вычитанием в уме.
Эта кнопка отвечает прямо — «свободно с 11:30 до 14:00», и умеет считать
сразу по нескольким календарям, если рабочий, семейный и спортзал у вас
разные.

## Что нужно для доступа

Вход по OAuth обычного аккаунта Google. Сервисный аккаунт не подходит:
он не видит личный календарь, пока календарь ему не расшарят.

```bash
GOOGLE_CLIENT_ID=…          # обязательно
GOOGLE_CLIENT_SECRET=…      # обязательно
GOOGLE_REFRESH_TOKEN=…      # обязательно
GOOGLE_CALENDAR_ID=primary  # основной календарь, по умолчанию primary
COACH_TZ=Europe/Moscow      # часовой пояс вывода
HTTPS_PROXY=…               # если Google недоступен напрямую
```

Где взять `refresh_token`: завести проект в Google Cloud Console, включить
Calendar API, создать OAuth-клиент типа «Desktop», пройти вход один раз
и сохранить полученный `refresh_token`.

**Опубликуйте OAuth-приложение** (статус Production). Пока оно в тестовом
режиме, Google гасит `refresh_token` через семь дней, и доступ будет
отваливаться каждую неделю без внятной причины.

## Установка

```bash
uv pip install -e .
```

Запуск как MCP-сервера (транспорт stdio):

```bash
gcal-mcp
```

В Claude Code сервер удобнее объявить пусковым скриптом, который сам достанет
секреты из хранилища, — тогда они не попадут ни в конфиг, ни в репозиторий.

## Тумблеры: что грузить в сессию

Описание каждой кнопки уезжает в контекст модели при каждом запуске. Для
одноразовой сессии это ничего не стоит; для агента, у которого контекст
копится, — стоит, и платит он этим местом всегда.

Поэтому набор выбирает тот, кто платит. Файл `~/.config/gcal-mcp/tools.yaml`
(путь меняется переменной `GCAL_TOOLS_FILE`):

```yaml
tools:
  list_calendars: off   # id календарей нужны один раз при настройке
  list_events: on
  find_events: on
  free_slots: on
  create_event: on
  update_event: on
  delete_event: on
```

Два правила:

- **кнопки нет в файле — она включена.** Обновились, приехала новая
  возможность — она работает сразу;
- **выключенная кнопка не объявляется вообще** — то есть не занимает места.

Проверить, что получилось: `gcal-mcp-tools`.

## Как устроено

```
client.py  — доступ: обновление токена, HTTP, часовой пояс
core.py    — логика кнопок, возвращает готовый текст для человека
tools.py   — манифест: единственное место, где объявлен список кнопок
server.py  — обёртка для внешнего мира (stdio), собирается из манифеста
toggles.py — тумблеры
table.py   — печать таблицы кнопок
```

Список кнопок объявлен **один раз**, в манифесте. Обёрток может быть
несколько — отдельный процесс и встроенный в агента, — но объявление
у них общее. Два списка, написанных руками, расходятся: рано или поздно
кнопку добавят в один и забудут про другой, и каждый по отдельности
будет выглядеть работающим.

Календарь бесплатный целиком — платных возможностей, которые пришлось бы
скрывать, у него нет.
